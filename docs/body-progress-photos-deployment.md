# Fotografias corporais privadas — implantação

1. Aplicar a migration versionada `supabase/migrations/202611060001_body_progress_photos.sql` no Supabase pelo fluxo habitual. Ela cria tabela, bucket privado, RLS, reservas de envio e proteção da exclusão de conta. Não executar apenas partes do SQL.
2. Publicar a Edge Function: `supabase functions deploy body-progress-photo-cleanup`. O `config.toml` desativa a validação JWT do gateway; o handler valida o bearer token pelo Auth, verifica a conta ativa e deriva o proprietário exclusivamente do usuário validado. Usa as variáveis padrão `SUPABASE_URL`, `SUPABASE_ANON_KEY` e `SUPABASE_SERVICE_ROLE_KEY` (ou `SUPABASE_SECRET_KEY`). Nenhuma chave administrativa vai para o frontend.
3. Publicar o frontend com os assets de `frontend/public/pose/`, os chunks de worker e a configuração CSP atualizada em `vercel.json`. Em outro host, permitir `'wasm-unsafe-eval'` em `script-src`, workers do próprio domínio e servir `.wasm` como `application/wasm`. Não é necessário liberar domínios externos para análise.
4. Publicar backend e frontend em uma janela coordenada: a nova exclusão de conta depende da Edge Function. Após aplicar a migration, clientes antigos não conseguem excluir a conta enquanto houver fotos; precisam atualizar o aplicativo.
5. Validar em staging com duas contas definitivas: criar foto, reabrir, comparar, ajustar, remover e excluir a conta; confirmar ausência dos objetos via Storage API. A exclusão SQL só prossegue após a limpeza; não apagar diretamente linhas de `storage.objects`, pois isso não remove os arquivos físicos.

Os envios usam reserva de metadados antes do arquivo e confirmação após o upload. Uma falha tenta remover reserva e objeto pela função. Se houver perda de conexão ou troca de conta, o histórico mostra o envio interrompido para exclusão explícita; “Limpar envios incompletos” coleta reservas e objetos sem referências com mais de uma hora, preservando uploads recentes. Exclusões parciais ficam marcadas e podem ser repetidas. A limpeza da conta considera apenas as reservas capturadas; um novo upload concorrente faz a proteção SQL bloquear a exclusão até nova tentativa.

Não há Realtime, polling, persistência de fotos no Zustand/JSON nem cache de fotografias no Service Worker. URLs assinadas duram 15 minutos e são reutilizadas apenas na memória da seção daquela conta. A ausência de rede impede consulta/upload; não há persistência fotográfica offline.

O modelo (~5,8 MB) e o WASM (~14,6 MB) são carregados sob demanda. Dispositivos sem worker/OffscreenCanvas/WASM compatível ou fotos com baixa confiança usam enquadramento original e ajuste manual. HEIC/HEIF depende do decoder do navegador; sem suporte, o usuário recebe instruções para exportar JPEG. Alinhamento preserva proporções e usa somente escala/deslocamento; não é garantia de equivalência anatômica entre poses, iluminação ou distâncias diferentes.
